# GEO DASH — документация админа

Всё про сервер, лицензионные ключи, оплату и обновления. Админ один: **Winnigames2024**
(аккаунт с таким именем получает права сам при входе).

Сайт: `https://geodash.winnigames2024.ru` · API игры: порт `37534` · данные API: `/var/lib/geodash`

---

## 1. Лицензионные ключи

### Как это работает

Ключ выглядит так: **`GD-XXXX-XXXX-XXXX-XXXX`**.

* Алфавит — без похожих друг на друга знаков (`I`, `L`, `O`, `U` не встречаются).
  Если игрок наберёт `O` вместо нуля или `I` вместо единицы, игра исправит это сама.
* Последний знак — контрольный. Описку игра видит сразу, не спрашивая сервер.
* Один ключ активируется **один раз** и навсегда остаётся за аккаунтом.
  На самом аккаунте он работает на **всех устройствах игрока** — и на ПК, и на телефоне.
* Ключей можно купить несколько: лишние лежат в аккаунте покупателя,
  их можно отдать друзьям — каждый активирует свой на своём аккаунте.
* У аккаунта админа игра открыта всегда, без ключа.

Игра пускает внутрь, когда выполнены два условия:

1. она поставлена установщиком (на ПК — метка `install.json` рядом с `GEO DASH.exe`,
   на Android — установка сделана приложением `com.winnigames2024.geodash.setup`);
2. на аккаунте активирован ключ.

Активация запоминается на устройстве, поэтому без интернета игра запускается как обычно.

### Выдать ключи ссылкой

```
https://geodash.winnigames2024.ru/api.php?action=getlicencekey&value=key:GEODASH_AADDMMIINN22002266JSD;format:json;
```

`value` — это пары `имя:значение`, разделённые `;`:

| поле     | что делает                                                        |
|----------|-------------------------------------------------------------------|
| `key`    | ключ админа (обязательно)                                          |
| `format` | `json` (по умолчанию) или `text` — тогда ключи придут простым списком |
| `count`  | сколько ключей выдать за раз, 1…50                                 |
| `note`   | пометка: кому и за что — видна только в админке                    |
| `user`   | сразу активировать ключ на этом аккаунте                           |
| `price`  | записать цену в карточку ключа                                     |

Примеры:

```bash
# один ключ
curl -s "https://geodash.winnigames2024.ru/api.php?action=getlicencekey&value=key:GEODASH_AADDMMIINN22002266JSD;format:json;"

# пять ключей простым списком, с пометкой
curl -s "https://geodash.winnigames2024.ru/api.php?action=getlicencekey&value=key:GEODASH_AADDMMIINN22002266JSD;format:text;count:5;note:розыгрыш;"

# открыть игру игроку Petya прямо сейчас
curl -s "https://geodash.winnigames2024.ru/api.php?action=getlicencekey&value=key:GEODASH_AADDMMIINN22002266JSD;user:Petya;"

# сколько ключей выдано, занято, свободно
curl -s "https://geodash.winnigames2024.ru/api.php?action=licenceinfo&value=key:GEODASH_AADDMMIINN22002266JSD;"
```

Неверный ключ админа отвечает `403` с задержкой — перебор бессмысленен.

Ключ админа по умолчанию `GEODASH_AADDMMIINN22002266JSD`; его можно сменить переменной
окружения `GEODASH_LICENCE_KEY` для php и `GEODASH_ISSUE_SECRET` для API (значения должны совпадать).

### Выдать ключи из админки

`/admin/` → карточка **«Лицензионные ключи»**:

* **ВЫДАТЬ КЛЮЧИ** — сколько угодно разом, с пометкой; ключи появятся строкой сверху, их нужно скопировать;
* **ОТКРЫТЬ ИГРУ ИГРОКУ** — ключ создаётся и сразу активируется на указанном аккаунте;
* таблица всех ключей: кто активировал, когда, пометка, заказ;
* **ОТОЗВАТЬ / ВЕРНУТЬ** — отозванный ключ перестаёт работать, игрок при следующем запуске
  снова увидит окно ключа.

### Где ключ видит игрок

**`/keys/`** («Ключи» в меню сайта) — все ключи аккаунта: активированный, свободные,
отключённые. Оттуда же игрок может ввести ключ, **временно отключить** его и включить
обратно. Пока ключ отключён, игра на этом аккаунте не запускается и просит другой ключ —
сам ключ при этом никуда не девается. Отозванный админом ключ владелец включить не может.

Коротко это видно и в `/account/`, в карточке «Лицензионный ключ».

### Покупка без аккаунта

Платить можно не входя: заказ заводится без покупателя, а после оплаты страница
`/buy/done.php` предлагает создать аккаунт (или войти в существующий) — и ключ из заказа
сразу закрепляется за ним, первый свободный активируется. Заказ привязывается один раз:
второй аккаунт его уже не заберёт. Номер заказа знает только покупатель — по нему ключ
и находится, если страница закрылась.

## 2. Оплата

Пошаговая инструкция с проверкой каждого шага и журналом уведомлений — на сайте:
**`/admin/pay.php`** (ссылка есть в админке, в карточке лицензий). Две вкладки —
ЮKassa и ЮMoney; настроить нужно что-то одно. Ниже то же самое коротко.

Способов два:

| | ЮKassa (магазин) | ЮMoney (кошелёк) |
|---|---|---|
| что нужно | ИП или ООО, договор, анкета | только кошелёк |
| деньги идут | на расчётный счёт | на кошелёк |
| чеки, возвраты | есть | нет |
| как платит игрок | карта, СБП, кошелёк | карта, кошелёк |
| настройка | `shopId` + `secretKey` | `receiver` + `secret` |

Если в `pay.json` заданы оба — работает ЮKassa.

Проще всего задать настройки **прямо в админке**: `/admin/pay.php` → вкладка нужного
способа → поля и кнопка **«Применить»**. Оплата включается сразу; данные хранит игровой
сервер в `/var/lib/geodash/pay.json` файлом только для себя (права 0600), сайт их обратно
не показывает — секрет в поле остаётся пустым, пока не нужно его заменить. Кнопки
«Выключить ЮKassa» и «Выключить кошелёк» убирают способ, не трогая остальное.

Второй путь — файл на сервере, как раньше. Он тоже читается, но то, что сохранено
кнопкой «Применить», важнее. Настройки оплаты **не лежат в репозитории**:

```bash
mkdir -p /etc/geodash
cat > /etc/geodash/pay.json <<'EOF'
{
  "shopId":    "",
  "secretKey": "",
  "receiver":  "",
  "secret":    "",
  "price":     199,
  "currency":  "RUB",
  "vatCode":   0,
  "issueKey":  "GEODASH_AADDMMIINN22002266JSD"
}
EOF
chown root:www-data /etc/geodash/pay.json
chmod 640 /etc/geodash/pay.json
```

Для ЮKassa: `shopId` — номер магазина, `secretKey` — секретный ключ API
(Интеграция → Ключи API; `live_…` рабочий, `test_…` тестовый).
Для кошелька: `receiver` — номер счёта ЮMoney, `secret` — секрет HTTP-уведомлений.
`price` — цена одного ключа в рублях. `vatCode` — ставка НДС для чека: `0` — чек не
формируем; если у магазина включена фискализация, задайте ставку, и страница покупки
попросит у игрока e-mail.

Адрес для уведомлений — свой у каждого способа:

```
ЮKassa:  https://geodash.winnigames2024.ru/api.php?action=yookassa
ЮMoney:  https://geodash.winnigames2024.ru/api.php?action=yoomoney
```

**ЮKassa**: адрес вставляется в Интеграция → HTTP-уведомления, событие
`payment.succeeded`. Подписи у её уведомлений нет, поэтому проверяем дважды: что
запрос пришёл с её подсетей и что платёж действительно оплачен — перечитываем его
запросом `GET /v3/payments/{id}`. Платёж создаём сами (`POST /v3/payments`), ключ
идемпотентности — номер заказа, так что повторное нажатие кнопки не создаёт второй платёж.

**ЮMoney**: адрес вставляется в настройках уведомлений кошелька, включить нужно **оба**
вида — переводы с кошелька и с карты. Приложение на `yoomoney.ru/myservices/new`
регистрировать не нужно: та страница выдаёт `client_id` для OAuth-доступа к кошельку
по API, а оплате и уведомлениям хватает номера кошелька и секрета. Подпись принимается и новая (`sign`, HMAC-SHA256
по всем полям, отсортированным по имени), и старая (`sha1_hash` с жёстким порядком полей).

Пока файла нет, продажа просто выключена: страница покупки говорит, что оплата не
настроена, а ключи по-прежнему выдаются ссылкой и из админки.

### Как идёт покупка

1. Игрок на `/buy/` выбирает количество → сайт заводит заказ `gd…` и показывает кнопку оплаты.
2. Платёжная система принимает оплату и присылает уведомление на свой адрес.
3. Уведомление проверяется: у ЮKassa — по подсети и перечитыванием платежа, у кошелька — по
   подписи. Не сошлось — ошибка, ключ не выдаётся.
4. Ключи выдаются **один раз на заказ**: повторное уведомление ничего не создаёт.
   Каждое уведомление пишется в журнал — последние 30 видны на `/admin/pay.php`.
5. Недоплата (меньше 90% от цены — допуск на процент карты) ключ не выдаёт, заказ помечается.
6. Ключи появляются в аккаунте покупателя и на странице `/buy/done.php?order=…`.

Посмотреть заказ (годится для обоих способов):

```bash
curl -s "https://geodash.winnigames2024.ru/api.php?action=order&order=gdXXXXXXXXXXXXXXXX"
```

## 3. Установка игроку

### Windows

`GEO_DASH_Setup.exe` с `/download/`:

* **всегда качает последнюю сборку** — сначала с сайта, потом с GitHub;
  файл рядом с установщиком берётся только когда нет интернета;
* поле **«Лицензионный ключ»** — не обязательное: игра спросит ключ при первом запуске,
  а введённый здесь активируется сама;
* ставит ярлыки, привязывает `.gdl`, кладёт рядом `autoupdate.exe` и службу обновления;
* пишет метку `install.json` — по ней игра понимает, что её поставили установщиком.

### Android

`GEO_DASH_Setup.apk` с `/download/`:

* качает свежий `GEO_DASH.apk` с сайта и ставит игру **от своего имени** (PackageInstaller),
  поэтому игра видит правильный источник установки;
* телефон один раз спросит разрешение «установка из этого приложения» — установщик сам
  откроет нужную страницу настроек;
* кнопка **«ОТКРЫТЬ ИГРУ»** передаёт игре введённый ключ.

Игра, поставленная вручную из `GEO_DASH.apk`, покажет окно ключа и попросит установщик.

## 4. Обновление сервера

Выложить то, что лежит в репозитории:

```bash
curl -s "https://geodash.winnigames2024.ru/api.php?action=updateserver&value=fj66yhKEY_tfde5ADMIN"
```

Заявка падает файлом `.update-request`, за ним следит systemd (`geodash-request.path`)
и обновляет сервер в тот же миг; минутный таймер остаётся на случай сбоя.

Проверить, что выложено:

```bash
curl -s "https://geodash.winnigames2024.ru/api.php?action=status"
```

Отдаёт версию, размеры и время выкладки `GEO_DASH.exe`, `GEO_DASH.apk`,
`GEO_DASH_Setup.exe`, `GEO_DASH_Setup.apk`, `autoupdate.exe`, а также включена ли продажа ключей.

Руками, с самого сервера:

```bash
curl -fsSL "https://raw.githubusercontent.com/Winnigames2024-Original/mods/main/GEO%20DASH/update.sh?v=$(date +%s)" | bash
```

## 5. Служебные адреса API

Лицензии (игра ходит сюда сама):

| метод | адрес | кто может |
|-------|-------|-----------|
| `GET`  | `/api/licence/mine` | игрок (его ключи и статус) |
| `POST` | `/api/licence/activate` | игрок (`key`, `device`, `platform`) |
| `GET`  | `/api/admin/licences` | админ (все ключи и сводка) |
| `POST` | `/api/admin/licence/new` | админ (`count`, `note`) |
| `POST` | `/api/admin/licence/grant` | админ (`name` — выдать и активировать) |
| `POST` | `/api/admin/licence/revoke` | админ (`key`, `revoked`) |
| `POST` | `/api/licence/issue` | только с самого сервера, с секретом |
| `GET`  | `/api/licence/stats` | только с самого сервера |
| `GET`  | `/api/licence/order/:order` | только с самого сервера |

Выдача ключей закрыта дважды: запрос принимается лишь с `127.0.0.1` **и** с верным
секретом, так что снаружи ключ не выпросить даже зная адрес.

Данные лежат в `/var/lib/geodash/licences.json` и `/var/lib/geodash/orders.json` —
обычный json, можно смотреть глазами и бэкапить вместе с остальными файлами.
